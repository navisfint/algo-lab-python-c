## 一、继承与函数

**共同点：** 三个实验都以「函数封装 + 主函数调用」为骨架，把游戏逻辑收进一个独立函数，`main()` 只负责随机数种子与调用，结构完全一致。

**差异：** 汉诺塔是**递归函数**，猜数与抓狐狸是**迭代函数**。这是三个实验最本质的分水岭——前两个的循环是「平铺的、可数次的」，汉诺塔的循环被函数自我调用取代。

```c
/* 15/16：迭代 —— 循环次数由 maxTimes / maxStep 直接决定 */
for (int i = 0; i < maxTimes; i++) { ... }

/* 17：递归 —— 规模每次减 1，由栈帧堆出"隐式循环" */
hannoi_impl(num - 1, src, temp, dst);
```

## 二、变量作用域

**共同点：** 都尽可能把状态限制在函数内部（局部变量），避免全局污染。

**差异：** 汉诺塔的「移动次数」和「三个底座」必须跨递归层共享，Python 用 `global times` + 模块级 `towers`，C 里对应的是**文件作用域的 `static` 变量**：

```c
static int  g_times = 0;                    /* 对应 Python: global times */
static int  g_stack[MAXTOWER][MAXN];        /* 对应 Python: towers 字典 */
static int  g_top[MAXTOWER];
```

猜数与抓狐狸则完全不需要全局态——狐狸的 `positions[]` 用 `calloc` 在函数内动态申请、函数结束前 `free`，是**纯净的局部生命周期**。这恰好说明：**只有递归/回溯类问题才需要跨层共享状态。**

## 三、数据结构

| 实验 | Python 版 | C 版 | 语义 |
|---|---|---|---|
| 15 | 标量 `value` | 标量 `int value` | 单值，无容器 |
| 16 | 列表 `[0]*n`，1 标记有狐狸 | `int *positions`（`calloc`） | 一维标记数组 |
| 17 | 字典 `{'A':[...],'B':[],'C':[]}` | `int stack[3][64]` + `int top[3]` | 二维数组模拟三栈 |

汉诺塔这里体现了 C 的一个关键取舍：Python 的 `list.append / pop` 自带动态容量，C 用**定长数组 + 手工栈顶指针**模拟。好处是无内存分配、无碎片；代价是容量必须在编译期定死（`MAXN 64`，正好对应教材里 64 个盘子的规模上限）。

## 四、输入约束与异常处理 —— 三份代码的共同难点

Python 用 `try / except` + `assert` 把「非法输入」交给异常机制兜住：

```python
try:
    x = int(input(prompt))          # 非数字 -> ValueError
    assert 0 <= x < n               # 越界   -> AssertionError
    break
except:
    print('要按套路来啊')
```

**C 没有异常机制，且 `scanf("%d")` 失败时会把非法字符留在输入缓冲区造成死循环**——这是最常见的坑。三份 C 代码统一改用「**按字符串读入 → 逐字符校验 → 循环重读**」的策略：

```c
static int read_int(int *out) {
    char buf[64];
    if (scanf("%63s", buf) != 1) return 0;      /* 读成字符串，不解析 */
    int i = 0, sign = 1;
    if (buf[0] == '+' || buf[0] == '-') { sign = (buf[0]=='-') ? -1 : 1; i = 1; }
    if (buf[i] == '\0') return 0;               /* 只有符号，非法 */
    for (; buf[i] != '\0'; i++)
        if (!isdigit((unsigned char)buf[i])) return 0;   /* 逐字符判定 */
    *out = sign * (int)strtol(buf, NULL, 10);
    return 1;
}
```

实验 15 把它嵌在 `for` 循环里（非法输入算作一次尝试，与 Python 版 `except` 后继续下一轮 `for` 一致）；实验 16 把它嵌在 `for(;;)` 里（非法输入**不消耗**猜测次数，与 Python 版内层 `while True` 一致）。

> 这个细微差别值得注意：同样是「拒绝非法输入」，**实验 15 的异常分支会推进循环计数，实验 16 的不会**。原因是 Python 原代码一个用 `for`、一个用 `while True`——这是从教材代码结构直接继承下来的行为，不是随意选择。

## 五、控制结构对照总表

| 控制结构 | 实验 15 猜数 | 实验 16 抓狐狸 | 实验 17 汉诺塔 |
|---|---|---|---|
| 主循环 | `for`（固定次数） | `while`（次数递减） | **递归**（规模递减） |
| 提前结束 | `break`（猜中） | `break`（抓到） | `return`（`num < 1` 出口） |
| 循环收尾 | `if (!guessed)` 模拟 `for-else` | `if (alive)` | 无 |
| 分支 | 三分支 `if/else if/else` | 位置判断 + 边界双分支 | 无显式分支 |

**关于 `for-else`：** Python 的 `for...else` 在「循环未因 `break` 中断」时执行 `else`。C 里没有这个语法，用标志变量等价模拟：

```c
int guessed = 0;
for (...) { if (猜中) { guessed = 1; break; } }
if (!guessed) { /* 等价于 for-else 的 else */ }
```

**关于默认参数：** Python 的 `def guessNumber(maxValue=10, maxTimes=3)` 和 `def hannoi(..., temp=None)` 都能省略实参。C 没有默认参数，两种应对：

- 实验 15/16：直接在 `main()` 里显式传值 `guess_number(10, 3)` / `catch_me(5, 10)`，简单直接。
- 实验 17：`temp` 是**算法内部的临时柱**，不是用户该关心的参数，所以用「同名薄封装 + 内部实现函数」把它彻底隐藏：
  ```c
  void hannoi(int num, int src, int dst)              { /* 对外：2 参数 */
      int temp = /* 从 src/dst 推出第三个底座 */;
      hannoi_impl(num, src, dst, temp);               /* 对内：4 参数 */
  }
  ```
  这比在 `main` 里手写 `hannoi(n, A, C, B)` 更贴合原意——教材的 `temp=None` 本意就是「调用者不必管」。

## 六、算法策略

| 实验 | 策略 | 复杂度 |
|---|---|---|
| 15 | 数值二分（猜大/猜小缩窄区间） | O(log maxValue) 最优 |
| 16 | **无信息搜索**——狐狸位置随机可知但移动方向随机，只能盲试 | O(n) 期望，最坏 O(maxStep) |
| 17 | **分治递归**（`n` 拆成 `n-1` + 1 + `n-1`） | O(2ⁿ) 步，n=64 需 1.8×10¹⁹ 次 |

汉诺塔还有一个**容易被忽略的约束**：题目要求「每次移动后输出三个底座的分布」。Python 的 `towers[dst].append(towers[src].pop())` 一行搞定，C 需要显式两步：

```c
g_stack[dst][++g_top[dst]] = g_stack[src][g_top[src]--];
```

这里 `++g_top[dst]` 是**先自增后取值**（栈顶上移一位再写入），`g_top[src]--` 是**先取值后自减**（读走栈顶再下移）——运算符的求值顺序恰好把「压栈 / 弹栈」一次表达完，是 C 里比较紧凑的写法。实测 3 盘输出 7 次移动，末态 `C: 1 2 3`，与理论值 2³−1 = 7 完全吻合。

## 七、一句话总结三者关系

> **实验 15 教循环里的分支（选择结构 + 异常约束输入），实验 16 教循环里的状态迁移（数组 + 边界处理），实验 17 教用递归替代循环（分治 + 跨层共享状态）。**
>
> 前两个是「同一种结构的两个变体」——都是「读输入 → 判定 → 更新状态 → 循环」，差别只在状态是标量还是数组、异常输入是否消耗次数；实验 17 则换了一条技术路线，用函数栈替代显式循环，并因此第一次引入了**全局共享状态**这一新问题。

## 八、Python ↔ C 语法映射速查

| Python 写法 | C 写法 | 出现在 |
|---|---|---|
| `value = randint(1, maxValue)` | `value = rand() % maxValue + 1` | 15 |
| `oldPos = randrange(0, n)` | `oldPos = rand() % n` | 16 |
| `choice((-1, 1))` | `(rand() % 2 ? 1 : -1)` | 16 |
| `positions = [0] * n` | `int *p = calloc(n, sizeof(int))` | 16 |
| `towers = {'A': [...], 'B': [], 'C': []}` | `int stack[3][64]` + `int top[3]` | 17 |
| `towers[dst].append(towers[src].pop())` | `s[dst][++t[dst]] = s[src][t[src]--]` | 17 |
| `positions[a], positions[b] = 0, 1` | `positions[a] = 0; positions[b] = 1;` | 16 |
| `global times` + `times += 1` | 文件作用域 `static int g_times` + `g_times++` | 17 |
| `def f(a, b=10)` 默认参数 | 同名薄封装调内部实现函数 / `main` 显式传值 | 15/16/17 |
| `for ... else` | `int flag = 0; for(...){...flag=1;break;} if(!flag){...}` | 15 |
| `try: int(input()) except:` | `scanf("%s")` 读字符串 + `isdigit` 校验 + 循环重读 | 15/16 |
| `assert 0 <= x < n` | `if (x < 0 \|\| x >= n) { 重新输入 }` | 16 |
| 列表越界抛 `IndexError` | **无边界检查**，越界即 UB —— 必须手动判范围 | 16/17 |
| 引用计数自动回收 | `free(positions)` 手动释放 | 16 |

> **最该记住的一条**：Python 的 `list` 越界会抛异常并给出清晰报错，C 的数组越界是**未定义行为**——可能静默写坏相邻内存、可能崩溃、也可能「看起来正常」。实验 16、17 里所有下标访问前的范围检查都不是冗余，是必需品。
